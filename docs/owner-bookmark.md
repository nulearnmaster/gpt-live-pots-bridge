# Permanent mobile bookmark (private owner mode)

Save `https://<your-private-voice-origin>/` in your phone's browser or add that same URL to your home screen as a shortcut. There is **no invite, registration, code, browser login, or browser credential to renew**. The URL stays the same across browser storage clears and server restarts. It works only from the authorized phone while its private network access and the service are available. The URL is not a public link or a secret. Open while parked and tap **비용에 동의하고 시작** for each conversation; the browser may still ask for the ordinary microphone permission. Opening or reloading the bookmark does not access the mic, create a provider session, or reconnect a prior call.

## Operator-only opt-in

Enable only behind a **private authenticated owner-device gate**, not a generic reverse proxy, a shared tailnet grant, a public reverse proxy, or Tailscale Funnel. The existing [parked smoke runbook](web-smoke.md) applies to cost, codecs/headset testing, parking, visibility and timeouts. This documentation is not a deployed setup or proof of a real provider/mobile test.

1. Pin the owner's exact authenticated identity **and** the intended phone's device membership at the edge. For Tailscale, use HTTPS Serve (tailnet only), an owner-phone-only tailnet access policy, and a gate that checks the authenticated Tailscale login and observed trusted source (the pinned phone's tailnet IPv4 and IPv6, if both available). Never accept a client-supplied identity or source header. The gate must trust only its private authenticated Serve hop, reject arbitrary local/public connections or use appropriately isolated processes/IPC, and fail closed on missing, duplicate, ambiguous or mismatched identity. A broad tailnet rule, DNS obscurity, or web `Origin` is not device authentication.
2. Gate **every** request (HTML, scripts, CSS and all API paths) before proxying. Strip all incoming copies of `X-Voice-Owner`, `X-Voice-Proxy-Key`, and untrusted forwarding headers. After authenticating the owner on the pinned device, stamp exactly one `X-Voice-Owner` with the exact configured login and one `X-Voice-Proxy-Key` using a privately generated 32-byte base64url key shared only by the gate and bridge service. Preserve the exact external `Host` and browser `Origin`; set `X-Forwarded-Proto: https` from the verified TLS transport. Forward only to the dedicated bridge port on IPv4 `127.0.0.1`. The bridge independently checks the loopback source, exact TLS/Host/Origin, exact owner and proxy key. Do not expose this port, log headers/bodies, send the proxy key to the browser/worker, or reuse the OpenAI credential. Trust the OS accounts running the gate and bridge; a compromised gate can impersonate the owner.
3. Use the same local state and worker configuration. In the service only, set `VOICE_WEB_ORIGIN` (exact bare HTTPS origin), `VOICE_WEB_OWNER_LOGIN`, and `VOICE_WEB_PROXY_KEY`; then, after separate approval for real voice charges, use `node src/cli.mjs serve --enable-paid-webrtc --enable-trusted-web-owner`. This mode disables `invite-web`. The normal `--enable-paid-webrtc` without the owner flag remains the invitation-based test flow. SIP and the worker still have their own activation flags and the queue remains shared. No network policy or service is configured by the repository.
4. Before any paid Start, confirm the bookmark opens on the pinned phone with no fragment/cookie, and fails off the private network, from another tailnet device (including another of the owner's devices), and for spoofed upstream headers. Test both v4 and v6 as configured. No need to click the paid Start button to verify access. To revoke a lost device, remove it from the network policy and gate immediately; stop the service if necessary to end a lingering call. If the proxy credential leaks, rotate it in both services. Do not change the saved URL unless the HTTPS origin changes.

Every Start includes its own explicit cost consent. An invisible, single-use in-memory permit lasts 15 seconds before the SDP exchange and only binds that attempt's lease/End; it is **not** an access link, enrollment key, or saved permission. No expiry is imposed on the bookmarked URL. Existing safety limits apply, including one concurrent SIP/web slot, the request burst limits, and a short drop-off lease. A confirmed End or a known start failure allows another explicit Start without a forced wait; the provider’s own limits still apply and there is no local duration cap. Reloading loses the old in-memory scope and there is no auto-reconnect; a previous call still closing may briefly block a new Start. Ambiguous provider outcomes remain fail-closed, as described in the [runbook](web-smoke.md).
