# Local test scope

Install the locked dependency once with `npm ci --ignore-scripts --no-audit --no-fund`. After installation, fixture signaling is on loopback and test media peers are local, with no API keys, Telegram, SIP accounts, live provider, or real Pots process:

| Command | What it exercises |
| --- | --- |
| `npm test` | SIP regressions: raw signed Live webhook, disarmed/unauthorized calls, expiry and duplicate deliveries, correct/incorrect keypad pairing, Live accept/attach contract, claim/dedup/hangup/restart, local CLI claim/completion and SQLite WAL crash durability. Web: origin/method/body/cookie/one-shot invite/consent, trusted-gate refusal (including raw loopback and forged/duplicate headers), stable root after restart without a cookie, scoped single-use permits, mutual exclusion, start spacing, `/v1/live/sessions` + `/attach` contract, browser response redaction, End during create, early final-event latch, and fail-closed cleanup across restart. Both exercise the same delegation, SQLite queue, worker and private target validation. |
| `npm run demo` | Both focused loopback protocol flows: two delegations while the first child is outstanding, continued socket activity, provider replay, hangup and restart, then a downstream fake Telegram result acknowledgment. |
| `VOICE_TEST_CHROMIUM=/absolute/path/to/chromium npm test` | Enables the otherwise skipped local browser fixture using a fresh headless profile, synthetic microphones and two native WebRTC peers. It checks a narrow viewport, invitation redaction, reopening the stable bookmark with no cookies and two distinct paid-start interactions (provider stub), no mic/start before consent, denied mic retry, cancellation while the mic or offer is still pending (no SDP POST, late stream stopped, no auto-resume), recovery from forced autoplay blocking, simultaneous RTP reception in both directions, no frontend event commands, and tracks stopped on End. The provider API is not exercised by this fixture; backend HTTP/WS is exercised by the protocol tests. Use an installed sandboxed Chromium; the test does not install anything. |

The protocol fixtures don't send audio and have no SIP stack. The optional browser fixture verifies bidirectional RTP with synthetic sources, not speech naturalness, Voice Activity Detection, a user actually hearing a receipt, Bluetooth routing, Safari/iOS, Chrome/Android, actual OS permission modals, or a provider's ability to hear an interruption. The fake local Pots executable verifies CLI arguments, receipts and duplicate wake/send handling, not actual Telegram delivery or an installed Pots main agent's handling of the child brief. These are separate acceptance criteria in the [mobile web](web-smoke.md) and [SIP](sip-smoke.md) manual smokes, both potentially billable.
